# Baseline mode/service ledger — provenance

`ledger/modes.v1.json` is the frozen baseline inventory required by outline
§6. It is **data only**: every entry is `not_started`, no mode is available,
and nothing here claims an adapter or decoder exists in this project.

## Source

- Generated by `tools/import_ledger.py` from the appendix of
  `docs/outline/WebSDR_Project_Outline-v0.1.md` (SHA-256 recorded in the
  ledger's `provenance.outline_sha256`). `make ledger-check` fails if the two
  ever diverge.
- The appendix was itself generated from the active registry entries of
  OpenWebRX+ (fork `K2AAM/openwebrx-k2aam`), `owrx/modes.py` at commit
  `86915038202fb273c13274420c7e882b32b19a0a`, git blob
  `ad85d5c7de124f0c125e5b045ada283a97acc1c9`, with the default WSJT-X and
  JS8Call requirements made explicit.

## Upstream comparison (2026-10-26)

Before freezing, the ledger was compared with the upstream file itself,
fetched read-only at the documented commit. The comparison
(`tools/diff_ledger_upstream.py`) parses the file with Python's `ast`
module; the upstream code was not executed, imported or copied into this
repository. Result:

- Upstream file git blob: `ad85d5c7de124f0c125e5b045ada283a97acc1c9` (expected `ad85d5c7de124f0c125e5b045ada283a97acc1c9`: match)
- Active entries in `Modes.mappings`: 74; ledger entries: 74
- Duplicate upstream ids: none
- In upstream but not ledger: none
- In ledger but not upstream: none
- Same order: yes
- Field differences: 0

**No discrepancies.** The ledger's ids, order, names, kinds and requirement
keys match the upstream registry exactly.

### Notes from the comparison (informational, not discrepancies)

- Kind follows the upstream constructor: the three `ServiceOnlyMode` entries
  (`audio`, `meteor-lrpt`, `elektro-lrit`) are the ledger's three
  background services; every other entry is a receiver/decoder mode.
- Upstream also marks some decoder modes (for example `navtex`, `dsc`,
  `msk144`) as usable by background services. The ledger keeps them as
  modes, as the outline does; how background decoding works here is decided
  when those integrations are built.
- Commented-out upstream entries (for example `mfrtty170`, `mfrtty450`) are
  not active registry entries and are not part of the baseline.
